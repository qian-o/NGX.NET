# NGX.NET

[![NuGet Version](https://img.shields.io/nuget/vpre/NGX.NET)](https://www.nuget.org/packages/NGX.NET)

C# bindings for NVIDIA NGX. The [Showcase](Showcase) provides a rendering example.

## Installation

```sh
dotnet add package NGX.NET
```

Requires .NET 10. The package has no additional runtime NuGet dependencies.

## Calling NGX

After initializing D3D12 with your native device, query feature availability:

```csharp
using NGX.NET;

NGXResult result = Ngx.D3D12.GetCapabilityParameters(out NGXParameter parameters);
if (Ngx.NVSDK_NGX_SUCCEED(result))
{
    try
    {
        result = Ngx.Parameter.GetI(parameters, "SuperSampling.Available", out int available);
        if (Ngx.NVSDK_NGX_SUCCEED(result))
        {
            Console.WriteLine($"DLSS available: {available}.");
        }
    }
    finally
    {
        Ngx.D3D12.DestroyParameters(parameters);
    }
}
```

Each function exposes its original pointer signature and at most one convenience overload combining eligible `in`, `ref`, `out` and nonnullable `string` parameters. The overload pins borrowed values and forwards to the same native entry point. Native parameter order and return values are preserved; failures do not become exceptions or replacement output values. Read outputs only when the SDK permits it. `Ngx.NVSDK_NGX_FAILED` and `Ngx.NVSDK_NGX_SUCCEED` retain the SDK macro semantics.

The existing Vulkan `Init` and `InitWithProjectID` string overloads accept `gipa` and `gdpa` as `nint` addresses obtained from a native loader. They cast those addresses to the exact function pointer types before calling the raw entry point. The raw signatures and all other callbacks remain typed function pointers. Callers must provide compatible functions and keep the loader, native module and related objects valid while NGX uses them.

The existing `Parameter.GetVoidPointer` and `SetVoidPointer` string overloads use `out nint` and `nint` for a single opaque address. Their raw entry points retain `void**` and `void*`. The getter forwards the caller's output slot without initializing or replacing the native output on failure. These methods do not dereference or own the address value. SDK-returned pointer arrays and typed callbacks keep their original pointer types.

Structures contain the native fields directly. Unions use overlapping fields, fixed-length arrays use concrete `InlineArray` types, and optional fields use null pointers. `NGXHandle` and `NGXParameter` are borrowed address values. Copying any of these values does not create ownership. Only explicit `new()` applies SDK member initializers; `default` and array elements remain zero-initialized.

## Strings and lifetimes

`NGXStrings` owns zero-terminated native strings. `AllocUtf8(string)` returns `byte*`; `AllocWide(string)` returns `void*` using UTF-16LE on Windows and UTF-32LE on Linux. The addresses remain stable until the owner is disposed. An empty string has a terminator; optional strings use a null pointer through the raw API.

For example, prepare an initialization search path inside an `unsafe` scope:

```csharp
using NGXStrings strings = new();

void* pRuntimePath = strings.AllocWide(Ngx.RuntimeDirectory);
NGXFeatureCommonInfo common = new()
{
    PathListInfo = new()
    {
        Path = &pRuntimePath,
        Length = 1u
    }
};
```

Pass `&common` to initialization while this scope is active. The pointer table and structure are caller-owned locals. Multiple paths can use a pinned `nint` array or a small `stackalloc` pointer table. `Dispose()` releases only the strings created by that owner; it does not release structures, SDK handles, callbacks or GPU resources. Repeated disposal is harmless; allocating after disposal throws `ObjectDisposedException`. Allocation, pointer use and disposal must not race.

String convenience overloads use a temporary `NGXStrings` for the duration of the call, including the direct strings passed to `InitWithProjectID`. They allocate and encode text. For frequent calls, prepare strings once or pin generated byte constants and use the raw entry point.

Keep every borrowed address alive for as long as NGX uses it. A normal array is stable only within its `fixed` scope. When NGX retains a structure or array address, use pinned storage and retain its owner. In particular, frame-generation helpers retain addresses of embedded matrices, and Vulkan helpers retain resource descriptor addresses. Keep them valid until the parameter table and associated SDK/GPU work no longer use them. Initialize pinned structure array elements explicitly with `new()` when SDK defaults are required.

A raw pointer does not keep `NGXStrings`, a pinned array or a delegate alive. Callbacks and their state must remain valid until NGX stops calling them; contain exceptions inside callbacks. SDK-returned strings and callback text are borrowed and must not be freed. Pair SDK initialization, parameter allocation and feature creation with their corresponding shutdown, parameter destruction and feature release calls.

## Platforms and binaries

Native NGX calls support `win-x64`, `win-arm64`, `linux-x64` and `linux-arm64`. Unsupported platforms are rejected when the native library is resolved.

The package includes `ngx-bridge` and NVIDIA DLSS feature libraries from `native/<rid>/`, packaged in `runtimes/<rid>/native/`. Linux assets retain their versioned `.so.*` names. Use `Ngx.RuntimeDirectory` in the initialization path list when loading the packaged feature libraries. Keep GPU resources and their native views alive for the entire submitted work lifetime.

## Updating bindings

Run the **Update NGX** GitHub Actions workflow to resolve one official SDK release and source commit. Every native target uses that same prepared input. Generated C++ translation units and linker inputs remain in runner scratch storage. Temporary workflow artifacts are deleted after all jobs finish, including failed runs, with a one-day retention limit as a fallback. The workflow compares the final PE/ELF exports with the extracted SDK declarations, then merges all four successful targets before regenerating bindings and updating the package version.

After generation, build and formatting checks pass, the workflow commits and pushes the complete native assets, `ast.json`, generated C# and package metadata update to the branch used to run it. A failed target or check prevents that commit. Python 3.13.16, matching LLVM/libclang 21.1.7 and Action commit SHAs are fixed; runner OS labels are explicit. Hosted image revisions and Visual Studio minor versions remain maintained by GitHub.

Regenerate and check the managed solution locally without compiling C++:

```sh
dotnet run --project NGX.NET.Generator -- .
dotnet build NGX.NET.slnx -c Release --warnaserror
dotnet format NGX.NET.slnx --no-restore --verify-no-changes --include-generated --exclude NGX.NET.Generator/obj NGX.NET/obj Showcase/obj --severity warn
```

The generator checks declarations across the four recorded targets. Managed builds and formatting checks do not establish NativeAOT execution or NVIDIA GPU runtime correctness; those require validation on the target platform.
